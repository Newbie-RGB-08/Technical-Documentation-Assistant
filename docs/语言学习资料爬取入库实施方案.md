# Java / Python / C++ / Go 学习资料爬取入库实施方案

> 版本：v1.0 · 日期：2026-10-27 · 状态：待确认执行  
> 原则：**零新代码开发**，全部复用 PTDRA 现有数据采集层与知识处理层能力。

## 一、项目现状分析（方案依据）

| 现有能力                         | 位置                                                                                 | 与本任务的关系                           |
| -------------------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------- |
| 爬虫服务（Crawl4AI，降级 httpx） | `backend/app/services/crawler.py`：`crawl_site()` / `save_crawled()`                 | 直接复用，Markdown 落盘 `data/tech_docs` |
| 增量入库管道（SHA-256 去重）     | `backend/app/services/ingest_pipeline.py`                                            | 直接复用，标题感知分块 + BGE 向量化      |
| 向量库                           | ChromaDB 持久化，`backend/data/chroma_db`，collection `tech_docs`                    | **向量存储落点**                         |
| 元数据库                         | MySQL `rag_meta` 库（documents / chunks / tags / document_tags / ingest_tasks 五表） | **元数据落点**                           |
| 入库 API                         | `POST /api/documents/ingest`、`GET /api/documents/status/{task_id}`                  | 触发入库与查进度                         |
| 知识源注册表                     | `backend/scripts/manage_sources.py`（authority A/B 分级）                            | 爬取前先登记来源                         |
| 建表脚本                         | `backend/scripts/init_mysql.sql`                                                     | 手工初始化 `rag_meta`                    |

**关键结论**：入库管道是"一份 Markdown → 同时写 ChromaDB 向量 + MySQL 元数据"，所以**不需要在"向量库 or 元数据库"里二选一**，走一次 `ingest` 两边自动落库，天然满足要求。

**需要处理的两个现状差异**：

1. `app/config.py` 默认 MySQL 密码为 `rgb123456!@#`，与本机实际密码 `root123456` 不一致 → 需在 `backend/.env` 中覆盖。
2. `documents.py` 路由只有 ingest/status/list，**没有暴露爬取端点** → 爬取这一步通过 Python 直接调用现有 `crawler` 服务模块完成（一条命令，非开发行为）。

## 二、目标与范围

- **爬取对象**：Java、Python、C++、Go 四种语言的入门教程、核心语法文档、学习路线图。
- **存储位置**：
  - 向量库：ChromaDB `tech_docs` 集合（`backend/data/chroma_db`）
  - 元数据库：MySQL `rag_meta`（host=localhost, port=3306, user=root, 密码经 `.env` 注入）
- **不做**：不修改任何现有模块代码；不做定时爬取；不爬需要登录/付费的内容。

### 步骤 2：准备种子 URL 清单（约 30 分钟）

建议爬取范围（按语言 × 主题组织）：

| 语言   | 学习路线          | 核心教程                                                                           |
| ------ | ----------------- | ---------------------------------------------------------------------------------- |
| Java   | roadmap.sh/java   | docs.oracle.com/javase/tutorial、javaguide.cn、runoob.com/java                     |
| Python | roadmap.sh/python | docs.python.org/zh-cn/3/tutorial、liaoxuefeng.com（Python 区）、runoob.com/python3 |
| C++    | roadmap.sh/cpp    | zh.cppreference.com、learncpp.com、runoob.com/cplusplus                            |
| Go     | roadmap.sh/golang | go.dev/doc/tutorial、go-zh.org（Go 语言之旅）、runoob.com/go                       |

操作：把每条线路的入口 URL（含深度抓取的站点根路径）整理成清单文件 `backend/data/crawl_seeds/` 下四个 txt（`java.txt` / `python.txt` / `cpp.txt` / `go.txt`），每行一个 URL。深度抓取时爬虫会自动限定同域名并抽取站内链接。

> 注意：cppreference 与 Oracle 部分页面反爬较严格，若 Crawl4AI 失败会自动降级 httpx + 清洗；仍失败则缩小到该站的稳定子路径。

### 步骤 3：执行爬取（每语言约 20~60 分钟，取决于站点规模）

调用现有 crawler 服务模块（在 `backend` 目录用 `.venv` 的 Python 执行，纯调用不写代码）：

```bash
cd backend
.venv/Scripts/python -c "
import asyncio
from app.services.crawler import crawl_site, save_crawled
from pathlib import Path

langs = {
    'java':   Path('data/crawl_seeds/java.txt'),
    'python': Path('data/crawl_seeds/python.txt'),
    'cpp':    Path('data/crawl_seeds/cpp.txt'),
    'go':     Path('data/crawl_seeds/go.txt'),
}
for lang, seed_file in langs.items():
    urls = [u.strip() for u in seed_file.read_text('utf-8').splitlines() if u.strip()]
    pages = asyncio.run(crawl_site(urls, max_depth=1, delay=2.5))
    out = Path('data/tech_docs') / lang
    saved = save_crawled(pages, out)
    print(lang, 'crawled:', len(pages), 'saved:', len(saved), '->', out)
"
```

- `del `

后端服务跑起来后（`start-backend.bat`），按语言分批入库，便于单独重试：

```bash
# Java
curl -X POST http://localhost:8000/api/documents/ingest \
  -H 'Content-Type: application/json' \
  -d '{"directory":"data/tech_docs/java","source_type":"tech_doc"}'
# 返回 task_id，用以下命令查进度
curl http://localhost:8000/api/documents/status/{task_id}
```

Python / cpp / go 同理，只改 `directory`。入库管道会自动完成：  
**SHA-256 去重 → 标题感知分块（512/64）→ bge-small-zh 向量化 → 写 ChromaDB `tech_docs` 集合 → 写 MySQL documents/chunks 表**。

重复内容已在库中的文件会自动跳过（增量机制），所以此步骤可安全重跑。

### 与原方案的偏差（环境问题修复）

1. **chromadb 1.5.9 在本机 Windows 上 Rust 绑定无法打开任何 sqlite 文件（code 14）**，且原 `_patch_chromadb_windows_sqlite_path` 补丁会让 sysdb 仅存内存（重启丢全部集合元数据）→ 降级 `chromadb==0.6.3` + `chroma-hnswlib==0.7.6a9`（该 win 轮子镜像缺货，用 curl 从 pypi.org 手动下载安装）。
2. **chromadb 0.6.3 默认 rollback-journal 在本机第二批写入起报 sqlite CANTOPEN**（sysdb 元数据静默丢失）→ `vector_store.py` 新增 `_patch_chromadb_sqlite_pragmas()`（`journal_mode=WAL` + `temp_store=MEMORY`）。
3. **`hnsw:sync_threshold` 默认 1000 且进程退出不强制刷盘** → 集合 metadata 设为 3，逐批持久化。
4. 方案引用的 `manage_sources.py` 实际不存在 → 新建（含 `knowledge_sources` 表 DDL 追加进 `init_mysql.sql`）。
5. 新增阶段测试 `tests/test_stage0~6_*.py`（方案原为"零新代码"，按开发要求补齐测试）。
